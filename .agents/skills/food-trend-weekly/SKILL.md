name: food-trend-weekly
description: Find food-video candidates directly in platform browsers, record original-page evidence, screen data with Python and generate Markdown weekly reports in explicit stages.
---

Read README.md, COLLECTION_STANDARD.md, config/weekly.json and the Markdown master. Honor the user's requested stage; report results and stop before the next stage unless authorized.

1. Discovery: directly browse the platform's actual UI. No MediaCrawler installation, collector command or API scraping is required. Fix one Asia/Shanghai anchor T for all platforms before browsing; use [T−7 days,T). Douyin uses past-week most-liked where available, Bilibili most-played with the same range; Xiaohongshu uses the food channel. Record actual options and coverage gaps. Open each selected video immediately and save complete observed URL including required query parameters, title, author, date display and metrics. Save every batch of at most five immediately to local JSONL; do not keep the only copy in browser memory. Record browser_video_v1 as specified in README. Never claim a card is a complete detail record. Retain original IDs as strings and video_key=platform:content_id; do not invent query tokens or reconstruct them.
2. Pipeline: import saved records with discovery, then run screen. Python handles exact date checks, 24h minimum age, deduplication and platform-specific metric priority. Do not silently change filtering. Unknown dates remain pending.
3. Verification: inspect originals and, when needed, video/subtitles; write checks.jsonl using README. Directly observed date text such as “2 days ago” or “edited on” must not be guessed into exact first-publication timestamps. Preserve display text, approximate/censored metrics and sources; missing numeric fields are null. Watching a page is not proof of virality. Save high-performance comparison basis separately. Stop on CAPTCHA and hand the page to the user; no repeated requests to bypass limits.
4. Reporting: run verify and report using saved evidence. Use the current Markdown master 01–08 structure. Dates/metrics must be traceable; incomplete candidates do not count as confirmed cases. No default Google Docs publishing.

Report ID uses date range, e.g. 2026-1115-1121; entry ID adds -001. Preserve original video IDs independently. Local raw data, URLs with access parameters, sessions and credentials must not be uploaded to GitHub. Browser login and platform access still may require user interaction. Legacy export adapters exist only for existing regression data; do not use them for new collection.
