## Existing pipeline

- Import the date folder with run_pipeline.py discovery --input-root data/YYYY/MMDD and a separate report run ID. This imports and freezes observations; it does not collect. Run screen only when requested; do not reimplement filters or ranking. Refer to the frozen run config for reproducibility.
- Verification inspects originals/video or reliable subtitles and records evidence in checks.jsonl. Read SCRIPTS.md for commands and outputs. Use priority_queue first, preserving multi-metric, backup, approximate, tie and lower-bound labels; check needs_review and reserve_candidates rather than treating them as exclusions. Relevance-uncertain complete records require content confirmation. Do not call the shortlist age-adjusted or automatically admit it to the report. Cumulative counts are not growth, older content may have longer accumulation, and sample leaders are not platform-wide leaders. Do not label collected old content a new weekly hit.
- Reporting uses existing verify/report commands and the Markdown master, followed by factual review. No default Google Docs publication or schedule.

Keywords, quotas and core metrics live only in config/discovery_policy.json; date archive and resume rules live in COLLECTION_STANDARD.md; fields live in DATA_FORMAT.md. Report IDs remain date ranges and entry IDs add -001. Keep original video identity platform:ID. Maintain the repository under AGENTS.md by replacing obsolete rules rather than accumulating duplicate instructions.
