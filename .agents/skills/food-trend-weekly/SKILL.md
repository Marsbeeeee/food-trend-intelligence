Read README.md, COLLECTION_STANDARD.md, DATA_FORMAT.md, config/weekly.json and the Markdown master. Honor the user's requested stage; report results and stop before the next stage unless authorized.

1. Discovery: directly browse the platform's actual UI. No MediaCrawler installation, collector command or API scraping is required. Fix one Asia/Shanghai anchor T for all platforms before browsing; use [T−7 days,T). Douyin uses past-week most-liked where available, Bilibili most-played with the same range; Xiaohongshu uses the food channel. Record actual options and coverage gaps. Open each selected video immediately and save complete observed URL including required query parameters, title, author, date display and metrics. Save every batch of at most five immediately to local JSONL; do not keep the only copy in browser memory. Record browser_video_v1 as specified in DATA_FORMAT.md. Never claim a card is a complete detail record. Retain original IDs as strings and video_key=platform:content_id; do not invent query tokens or reconstruct them.
2. Pipeline: import saved records with discovery, then run screen. Python handles exact date checks, 24h minimum age, deduplication and platform-specific metric priority. Do not silently change filtering. Incomplete data must be completed or discarded, never queued. Follow COLLECTION_STANDARD.md quotas and stop limits; DATA_FORMAT.md defines completeness.
3. Verification: inspect originals and, when needed, video/subtitles; write checks.jsonl using DATA_FORMAT.md. Directly observed date text such as “2 days ago” or “edited on” must not be guessed into exact first-publication timestamps. Preserve display text, approximate/censored metrics and sources; missing numeric fields are null. Complete means required observations exist, not fabricated precision: use supported published_date when exact time is unavailable and metrics_display for approximate counts. Only edited dates remain insufficient. See DATA_FORMAT.md; never force uncertain age groups or rank rounded values as exact. Watching a page is not proof of virality. Save high-performance comparison basis separately. Stop on CAPTCHA and hand the page to the user; no repeated requests to bypass limits.
4. Reporting: run verify and report using saved evidence. Use the current Markdown master 01–08 structure. Dates/metrics must be traceable; incomplete candidates do not count as confirmed cases. No default Google Docs publishing.

Report ID uses date range, e.g. 2026-1115-1121; entry ID adds -001. Preserve original video IDs independently. Local raw data, URLs with access parameters, sessions and credentials must not be uploaded to GitHub. Browser login and platform access still may require user interaction. Only browser_video_v1 is supported by the active workflow; obsolete collection/export code was removed.

The objective is high-performing food videos for reference, not collecting any food content. Python compares observed platform metrics after collection; use priority_queue first for content review, but explain comparison cohort and missing metrics. Codex inspects video form and usefulness; Python cannot infer them from counts. Keep per-platform input folders, complete links and provenance. Use config/discovery_policy.json as the sole source of keywords, quotas and required metrics. Incomplete records are discarded with aggregate reasons only; do not retain a pending pool. Do not invent a full-platform ranking from this sample.
