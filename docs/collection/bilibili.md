# B站采集操作

配额、记录命令和停止条件遵循[采集标准](../../COLLECTION_STANDARD.md)；本文件只记录页面操作经验。

1. 复用现有B站标签并确认登录。需要扫码时展示真实当前二维码，用户完成后复查登录状态和一条视频的评论总数，不立即放大到整批等待。
2. 搜索配置关键词并确认真实输入值和结果。上次某个搜索框替换文字后出现“美食烘焙”拼接；遇到这种情况先全选清空再输入，确认关键词后提交。结果加载期间不要从占位符或上一轮卡片提取候选。
3. 优先最多播放；海外页面或当前布局未提供可用排序时如实记录综合。烘焙结果可能包含游戏模组、贴图烘焙等，卡片明确无关就跳过，不凑数。
4. 从当前搜索结果提取实际BV链接，登记attempt再打开详情，核对标题和BV身份。读取播放、点赞、投币、收藏、分享，并取评论区标题旁的评论总数；播放区旁的弹幕数不能代替评论数。
5. 评论可能在惰性加载的组件/影子DOM中。上次仅键盘End会越过加载区域；点击“评论”定位，再在页面实际评论区域少量滚动，等标题旁数值出现后才读。需要坐标滚动时先观察当前页面，不能照搬旧截图坐标。等待达到当前工具期限就记录detail_timeout，停止盲重试；验证/访问限制则按采集标准停该平台。
6. 读取数值时去掉前后空白。上次播放量“ 2.8万”曾被误判缺失。投币或收藏只有文字标签时不能补0；每批交给collection.py确认完整和落盘。

上次可用定位线索：h1、.view.item、.video-like-info、.video-coin、.video-fav-info、.video-share-info-text；作者资料链接；评论标题相邻的#count。评论计数可能需要通过当前可见标题定位后读取其组件内相邻元素，不应直接假定全局document.querySelector能穿透组件。只读已呈现页面，不另找未验证的后台接口代替证据。

这些是上次可用的页面经验，不是固定接口。控件或结构变化时重新观察；常规批次不必每条都截整页，只在定位或异常时截图。独立平台会话未验证前不并行抢焦点，避免超时和重复登录。
