# 抖音采集操作

配额、记录命令和停止条件遵循[采集标准](../../COLLECTION_STANDARD.md)；本文件只记录页面操作经验。

1. 复用能访问抖音的现有浏览器标签，先确认登录。若需扫码，展示当前真实二维码再请用户操作，完成后复查页面，不另开一个未登录的隔离会话冒充原会话。
2. 搜索配置关键词。提交后确认输入框和实际结果已切换，不能只看刚输入的文字。优先最多点赞；未成功选中时记录综合，不写成热度排序。
3. 在当前结果中批量读视频卡片，先跳过明确无关或同日已存ID。卡片暂不提供ID时，用关键词、作者和完整标题构成稳定attempt key，登记后再打开详情。
4. 等当前弹层中的视频标题、作者和互动都已加载，再读点赞、收藏、评论、分享；确认内容与点开的卡片一致。一次性读取同一活动播放器的数据，不混用背景页面或推荐视频的数字。检查视频元素只能证明播放器存在，仍需确认对应内容是视频。
5. 从当前地址提取modal_id；有modal_id时它才是当前弹层视频ID，不能取地址中可能残留的旧/video/ID。保留完整地址与必要查询参数。独立视频页才从实际/video/ID读取身份，不把未打开验证的拼接链接宣称为已验证链接。
6. 保存观测后关闭弹层回到结果。此次实际可用的是Escape；浏览器后退有时会离开搜索，下一条箭头有时隐藏，先看当前状态再选择操作。扩展结果前确认已加载，避免页面仍是占位符时反复滚动或切词。

上次可用定位线索：卡片标题.hu36PKCP；活动播放器.modalPlayer.xgplayer-playing；data-e2e里的video-desc、feed-video-nickname、video-player-digg、feed-comment-icon、video-player-collect、video-player-share。它们不是平台接口承诺，每次必须从当前页面确认再用。先等字段就绪，再读取，不能靠固定延时假定成功。

标签“收藏/评论/分享”不是数值0；先去除数值前后空白，约数按DATA_FORMAT.md保留。每批交给collection.py append确认落盘；不要在浏览器内重写去重或数值转换规则。截图和完整长页面只在需要定位/登录时获取，常规检查用目标字段，减少无关输出。
